# SPEC-HAL-362 real macOS conformance capture

The executable has two separate capture modes and an offline analysis mode. The default native-adapter mode uses the production macOS lock adapter and relative-motion conversion with a diagnostic ingress binding; it does not open a production semantic lease. The debug-only `--engine` mode runs the actual `App::run` lifecycle with a mounted relative-gesture owner, `EventRouter`, hard capture, `RelativePointerLeaseAuthority`, `InputFusion`, and the same native lock adapter. Its conformance wrapper reports the native production support result and only substitutes a labeled diagnostic normalization-support response when that result is `NormalizationUnavailable`. The modes are evidence tools; they do not change ordinary `AppConfig` or the production support result.

From the repository root on macOS, run `cargo run --bin relative_pointer_macos_conformance`. This single synchronous command opens the capture window. The window title shows the next action; the terminal's `COVERAGE` and `NEXT` lines show the full current coverage and instruction as evidence arrives. `Q` records shutdown from an active lock and exits even when other coverage is incomplete, so previously proven motion and edge scenarios need not be repeated in a later lifecycle capture. The program saves absolute `.jsonl` evidence and `.verdict.json` PASS/FAIL/UNPROVEN report paths under `target/relative_pointer_macos_conformance/`, prints any automatic FAIL, then lists only the short observations that still need a person. An incomplete single run returns an error after saving its partial report; separate runs require review together and are never blindly concatenated because lease IDs restart. Move the pointer inside the window before each `L`, especially after moving the window or ending a lock, so a fresh window-local logical `DownAnchor` is available. The window need not render content.

For real engine lifecycle capture, run `cargo run --bin relative_pointer_macos_conformance -- --engine` in a debug build. Click and drag the primary mouse button within the window to commit the diagnostic gesture, move while locked, then release for normal completion. Repeat a fresh drag before each termination: press `U` to remove the actual mounted owner, `M` to remount it, `C` to request a same-frame semantic cancellation from `Screen::update`, use Cmd-Tab for real focus loss, and press `Q` during an active gesture for application shutdown. The `.engine.jsonl` and `.engine.verdict.json` files under the same target directory record native operations and the actual engine lease/capture/session state. The report requires ordered cleanup and same-frame cleared state for each trigger; missing operator actions remain UNPROVEN. Its aggregate production-admission row is evidence-only and stays UNPROVEN even if the lifecycle passes, because separate source, denial, and human observations lie outside that JSONL. After every cleanup, observe that the cursor is visible and usable; JSONL cannot establish that visual fact. The engine mode is a second run of the same executable, not a second event loop inside `App`.

To recalculate saved native and engine reports after a conformance-analyzer correction, build the current binary and run `for capture in target/relative_pointer_macos_conformance/*.jsonl; do ./target/debug/relative_pointer_macos_conformance --analyze "$capture"; done`. This mode opens no window and uses the same analyzer as live capture. It validates the capture identity, JSONL syntax, and contiguous record sequence before replacing each adjacent `.verdict.json`; the source `.jsonl` is unchanged. The output separately states whether native coverage completed or the engine run returned. A partial capture can prove individual observed checks but leaves absent obligations UNPROVEN; it does not change production support.

Use these inputs while the harness window has focus:

| Input | Operation and evidence |
| --- | --- |
| `L` | Acquire the actual macOS cursor lock and hide the cursor. Pressing again while locked optionally records the adapter's duplicate-lock denial; it does not prove native OS denial or gate capture completion. |
| Mouse movement | While locked, move far enough for the accumulated logical deltas from `DownAnchor` to cross each window edge, then continue for three outward samples. The harness checks the numeric crossing against the live logical window extent; there are no operator edge markers. |
| Primary-button drag | While locked, hold the primary mouse button and drag until a real `CursorMoved` callback is recorded at the chosen scale. The report checks that its absolute motion does not reach the fused semantic stream. |
| `R` | Restore the saved `DownAnchor` while hidden only if focus, monitor and backing scale still match; then release and show. |
| `U` | Release and show without restoration. |
| `X` | Simulate the owner unmount cleanup trigger. This tests adapter cleanup, not a real engine unmount. |
| `D` | Clean up, destroy the window and create a fresh one in the same run. The close button exercises the same path. |
| `Q` | During an active lock, clean up on shutdown and exit. Missing coverage remains UNPROVEN in the partial report. |
| `Z` | Abort an incomplete capture; save the partial report and exit with failure. |

Use one available real backing scale, 1× or 2×, for the pinned AppKit point-unit identity capture; changing the display mode solely to obtain the other scale is unnecessary. At that scale, move right, left, down and up while unlocked, then lock and repeat, collecting at least eight motion samples in each state. Continue each direction until the tracked virtual position crosses the corresponding logical window edge and three further outward samples arrive. A lock starts only with a bounded window-local `DownAnchor`; the report derives each crossing from that anchor, the window extent and the same canonical deltas sent through input fusion. If the window extent changes during a lock, press `U` and then `L` to recapture its current size. While locked, also hold the primary button and drag until a real `CursorMoved` callback is recorded. The `device_mouse_motion` records contain the winit-native delta, the adapter's logical delta, the fused relative delta, the window scale and the unconverted Quartz global cursor location. `cursor_moved` records contain physical and logical window positions and the count of fused absolute pointer moves. The report rejects missing samples and directions at the chosen scale as UNPROVEN and flags any conversion, absolute leakage or cleanup failure at any observed scale. The pinned winit/AppKit source audit and production `relative_motion_from_device_event` path with no scale arithmetic establish the point-unit identity; the real locked/unlocked capture checks that path in operation. A physical-pixel or scale-dependent backend would still require two real scale factors under §12.2.3.

The guide requests a lock followed by `R`, `U`, `X`, `D`, focus loss through Cmd-Tab, and finally `Q`; re-enter the window and lock for each cleanup. Duplicate `L` is optional because its adapter-level denial cannot satisfy the native-denial requirement. After Cmd-Tab, the cancelled drag must stay cancelled and the pointer must be visible inside the window without a click, even if the primary button remained down during the switch. The native `focus_changed` and engine `engine_cursor_rects_refreshed` records show whether the pinned AppKit cursor-rectangle refresh ran on focus regain; they cannot prove visibility. Separately for §12.2.7, move the unlocked window to another physical display, lock and move there, release, and confirm that the pointer remains visible and usable on both displays; the displays may have the same backing scale. A single-capture multi-display verdict remains UNPROVEN when that observation lies in a separate run or human testimony; the admission review below combines these sources explicitly. Check visibility and usability after every termination; JSONL alone cannot prove that the pointer is not stranded. If a monitor or scale change occurs while locked, the report separately checks that cleanup releases and shows without a restore operation. Missing invalidation evidence remains UNPROVEN for that subclaim. `R` also skips the warp if the recorded safe context no longer holds.

`L` twice proves adapter-level duplicate-lock denial only. The pinned `winit 0.30.12` macOS `window_delegate.rs::set_cursor_grab` calls `CGDisplay::associate_mouse_and_mouse_cursor_position(false)` for `Locked` and returns its CoreGraphics error; Halcyon's `relative_pointer_macos.rs::set_locked` maps that error to `Denied`. Neither API exposes a verified safe, deterministic public way to force this native call to fail. A wrong window, `Confined`, duplicate `L`, or injected error is not a genuine native denial. A gate-inactive `Denied` record needs review of prior release state before attributing it to the OS. If a genuine denial occurs naturally, preserve its JSONL record and check that the cursor remains visible with no native lock. If it occurs in `--engine`, also check the typed terminal outcome and cleared lease, capture, and session.

SPEC-HAL-362 §12.2.1 permits the documented unforceability plus deterministic Section 12.1 denial-path proof only for that unavailable native stimulus. The adapter's `native_adapter_rejects_denied_lock_and_cleans_up_after_restore_failure` test and the routed `denied_platform_lock_clears_the_gesture_without_hiding_the_cursor` test cover the typed `PlatformLockDenied`, no hide, and cleared engine state; their passing results must be recorded separately against the implementation revision. The native verdict deliberately leaves item 12.2.1 `UNPROVEN` because its JSONL cannot certify source audit or test execution. A reviewer must combine those independent facts with real acquisition/release evidence; all other §12.2 requirements remain real-backend obligations.

The default mode's diagnostic `X` action is not a real engine unmount; use `--engine` and `U` for that separate lifecycle evidence. Pointer visibility/no-stranding needs observation on the actual displays. Neither mode alone marks §12.2 complete.

## Production admission review, 2026-09-23

The pinned `winit 0.30.12` AppKit point-unit source audit in SPEC-HAL-362 §10.1 and the scale-independent production conversion in `relative_pointer_macos.rs::relative_motion_from_device_event` establish the normalization provenance. Native captures `1790172344935.jsonl` on external `Monitor #12804` and `1790174377961.jsonl` on built-in `Monitor #41055` each record six successful real lock/release cycles at 2×, complete locked/unlocked direction and four-edge coverage, stable Quartz location while locked, locked absolute callbacks without fused absolute motion, and safe same-window `DownAnchor` restore. The second capture also records successful AppKit cursor-rectangle refresh after Cmd-Tab. Their automatic §10.1 and §12.2.2–5 rows PASS.

For §12.2.1, no genuine native OS lock refusal occurred. The pinned winit/CoreGraphics call offers no verified safe deterministic public refusal trigger; the adapter maps its error to `Denied`. The separate `native_adapter_rejects_denied_lock_and_cleans_up_after_restore_failure` and `denied_platform_lock_clears_the_gesture_without_hiding_the_cursor` tests prove the permitted deterministic adapter-to-engine denial path: typed `PlatformLockDenied`, no hide or surviving lease, and cleared capture/session. The native report correctly leaves this independently reviewed fact UNPROVEN.

For §12.2.6, both native captures record active focus/app-switch, window destruction, and shutdown cleanup; native `X` is only simulated. Real App capture `1790174482701.engine.jsonl` records six PASS lifecycle rows, including actual owner unmount, semantic cancel, focus loss, normal Up and shutdown, with same-frame cleared lease/capture/session. The operator reported no problems after repeating native and engine runs on the second display, in response to the two-display visibility question; the preceding post-fix engine run `1790173599543.engine.jsonl` was likewise reported clean. Taken with real lock/release captures on both physical displays, this is the human visibility/usability/no-stranding observation for §12.2.7. Focus loss and other forced cancellations performed release/show without restore. No monitor or backing-scale transition happened during an active lock, so the separate transition-specific no-warp rows remain UNPROVEN rather than being claimed as observed.

The admission decision combines those independent facts under §10.1 and §12.2. A capture's aggregate `production support admission` row remains UNPROVEN because JSONL cannot certify source audit, separate tests, and human observation by itself; it is not the live `RelativePointerPlatform::support` result. Production macOS `RelativeLocked` now advertises the pinned point-unit normalization epoch and `DownAnchor` restoration for the bound window; acquisition remains fallible, and every forced cancellation remains no-warp.
