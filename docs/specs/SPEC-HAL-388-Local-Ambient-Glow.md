# SPEC-HAL-388: Local Ambient Glow

**Status:** ADOPTED / BINDING for the first S1 renderer/paint profile defined in §7, per JC's 2026-11-13 explicit implementation instruction; §7 controls where earlier candidate text is less precise. No other material, physical light transport, default Button skin, glass, grain or rim is activated.
**Date:** 2026-11-13.
**Owner:** Halcyon paint and renderer, under HAL-012 appearance and HAL-359 composition.
**Confirmed JC direction:** Ambient Glow is an independent effect, not an obligatory Glass or Rim Light component.
**Governing owners:** HAL-002/002A, HAL-012, HAL-024, HAL-085A, HAL-354, HAL-359 and existing HAL-358 for contour-only illumination.
**First user result:** A dark primary button has a restrained, spatially bounded soft luminous pool around and behind it; its actual face, caption and hit target remain unchanged.

## 1. Meaning and scope

Local Ambient Glow is self-authored emitted-looking illumination around one element. It is a localized two-dimensional halo, not verified physical illumination cast onto independently rendered neighboring materials, a global bloom pass, a shadow, a focus-owner state, or a second glowing border. A nearby surface may *appear* illuminated because it lies beneath composited glow pixels; its own material/shading input is not mutated.

Its value is independent of the base material (Solid, Gradient, Smoked/Frosted), reflection (HAL-389) and contour emission (HAL-358). Product styles select explicit glow where meaningful, such as a primary action or current selection, without granting the renderer power to decide which action is important.

## 2. Proposed authored optical description

**INV-388-001 FINITE LOCAL LOBES:** A checked immutable glow value has zero, one or two independently authored elliptical lobes, each with finite straight-linear RGB source hue and source alpha a_i in [0,1], local-UV center, positive physical/logical radii, intensity i_i in [0,1], and finite bounded orientation. For the first proposed profile, each lobe's effective maximum outset from the owning rect is <=48 logical pixels, with current DPR conversion owned by the renderer. Invalid, negative or oversized requests fail rather than silently expanding layout or being clipped to a fake smaller footprint.

**INV-388-002 EXACT COMPACT FALLOFF:** For lobe k, transform current local point into its rotated elliptical coordinates: q_k=sqrt((x_k/rx_k)^2+(y_k/ry_k)^2). Define u_k=clamp(1-q_k,0,1) and f_k=u_k*u_k*(3-2*u_k). Thus f=1 at center, f=0 and first derivative zero at and beyond q>=1, with no rectangular Gaussian truncation seam. Effective lobe alpha is w_k=source_alpha_k*intensity_k*f_k. All inputs and intermediate values are finite; outside finite ellipse no halo pixels are emitted. This initial polynomial is the normative candidate for later adoption; it is not a 'truncated Gaussian' in disguise.

**INV-388-003 MATERIAL INDEPENDENCE:** With halo intensity zero, the material face, text, focus, border and retained scene remain identical to the baseline. The glow does not need an inner border, halo emitter contour or “glass” source; no hidden illumination is appended when a control is merely dark or selected.

**INV-388-004 EXACT TWO-LOBE MERGE AND COLOR:** With k=1..2 and w_k in [0,1], combine lobes *commutatively* rather than by order-dependent repeated OVER. Let w_sum=w_1+w_2, A=1-(1-w_1)*(1-w_2). If w_sum=0, output exact RGBA zero. Otherwise C=(w_1*C_1+w_2*C_2)/w_sum with source-hue straight-linear RGB C_k in [0,1], and output (A*C,A) in linear premultiplied RGBA, with ordinary inherited clip/coverage applied only by its existing owner. This bounded source-over-like coverage union is not physically additive HDR light transport, and no hidden third light or saturated bloom is implied. Equal lobe order and zero intensity yield identical output.

## 3. Geometry, layering and ownership

**INV-388-005 NONINTERACTIVE OUTSET:** Glow draw coverage may extend beyond the allocated button/panel face but never changes layout, hit-test rect, scroll extents, reveal, focus/capture geometry or child order. It remains inside the actual admitted ancestor clips and compositor surface. Hiding or unmounting the source removes its glow via normal retained composition.

**INV-388-006 STRICT Z AND SOURCE TRUTH:** Authored owner places a halo below its own face, text and mandatory cues by strictly different Z under HAL-359 and within the existing closed owning clip/surface. Equal-Z emission order cannot establish back/front semantics. The single resolved glow appearance consumes actual owner-provided state; it cannot automatically create a new selected/focused semantic state or independent overlay. The finite halo may overlap adjacent visible pixels *within the same lawful clip* but does not mutate adjacent materials or become an interactive surface.

**INV-388-007 STATE SOURCE:** Hover, pressed, selected and disabled facts may modulate this decoration only when their existing owning widget/product policy explicitly supplies them. The effect does not infer user semantics, consume pointer input or create a second focus cue. Static glow has no Timeline handle or continuing frame demand; a separately admitted animation, if ever requested, uses only the existing lawful Timeline owner.

**INV-388-008 SINGLE EFFECT:** The normal implementation should use the existing renderer's finite analytic surface/shape machinery when capable. HAL-358 already handles thin luminous contours with a radius bound and optional local fronts; it is reused for contours, not generalized by secretly attaching extra strokes or glow passes around a button. A broad elliptical area may require a distinct *bounded* direct paint primitive after source owner proof, not a general bloom engine.

## 4. Prohibitions

**FORBID-388-001:** No automatic glow on all controls, full-screen bloom, light propagation graph, globally mutable light list, third-party shader or new per-widget GPU owner.
**FORBID-388-002:** No change to focus/capture meaning, enlarged interaction, clip escape, cross-surface light claim, text blur, shadow-as-light substitution or repeated fake radial borders.
**FORBID-388-003:** No unbounded bloom, hidden timer, permanent redraw demand, silent fallback to a plain border or unverified emission-energy claim.

## 5. Conformance and intended use

A later owner unit must prove finite/invalid parameter rejection, the stated smoothstep polynomial with exact zero at/outside both elliptical support boundaries, a strictly continuous boundary with zero slope, full [0,1] channel/alpha bounds, commutativity of two-lobe union, zero-lobe and zero-intensity exact absence, no double composition or equal-Z reliance, owned ancestor clipping, unchanged hits/text/focus, retained replacement on hide/unmount and no idle repaint. Native 1x/2x tests compare off, one-lobe and two-lobe primary actions through real rest/hover/pressed/disabled states, with JC selecting the visible balance. No runtime implementation, physical energy transport or benchmark is claimed.

No hardware performance measurement, source code change or native appearance claim follows from this inactive candidate.

### 7.2 Validated public value and emission

The checked value `LocalAmbientGlowAppearance` holds an inline fixed count of 0..=2 `LocalGlowLobe` values, with no allocation for lobe storage. Each `LocalGlowLobe::try_new(center_uv: Point, radii: Point, rotation_cos_sin: Point, color: Color, intensity: f32) -> Result<Self,LocalAmbientGlowError>` validates: both center_uv components finite and in [0,1]; both radii finite in [0.5,48] logical pixels; rotation finite with squared cos/sin length in [0.9999,1.0001]; straight-linear color RGBA each finite in [0,1]; intensity finite in [0,1]. The checked `LocalAmbientGlowAppearance::try_new(lobes: &[LocalGlowLobe])` copies 0..=2 into inline ownership and rejects over-capacity, nonfinite, out-of-range or non-unit input via distinguishable typed `LocalAmbientGlowError`. No implicit normalization or clamping. A zero lobe count or all lobes with zero effective alpha generates no primitive, GPU work or frame demand.

`PaintSink::push_local_ambient_glow(&mut self, rect: RectF, appearance: LocalAmbientGlowAppearance, z_index: ZIndex, key: Option<SceneNodeKey>) -> Result<(),LocalAmbientGlowError>` is the public paint operation; `SceneBuilder` supplies its exact checked implementation. Existing non-SceneBuilder PaintSink implementations preserve source compatibility through a typed `UnsupportedPaintSink` default refusal, never a panic, dropped requested effect, or success-without-render. The given destination rect remains the existing owner-provided geometry, with finite logical origin/endpoints and finite strictly positive dimensions for a visible effect, all absolute coordinate magnitudes <=1048576; empty extents emit nothing. Validation and typed errors precede scene-node emission. No widget owns Device/Queue, GPU buffer, renderer target or backdrop source.

### 7.3 Identity, exact shader packing and bounds

### 7.4 Exact bounded fragment equation

For each active lobe k and fragment world-position p, compute delta=p-center_k; rotate by its checked cos/sin to x_k,y_k; compute `q_k=sqrt((x_k/rx_k)^2+(y_k/ry_k)^2)`, `u_k=clamp(1-q_k,0,1)`, `f_k=u_k*u_k*(3-2*u_k)`, `w_k=color_k.a*intensity_k*f_k`. With `w_sum=w0+w1` and `A=1-(1-w0)*(1-w1)`, when w_sum=0 output exact RGBA zero; otherwise `C=(w0*color0.rgb+w1*color1.rgb)/w_sum`, output `vec4(C*A,A)`. Each component is finite in [0,1], premultiplied-linear and independent of authored lobe order. At the ellipse support q>=1 both value and first derivative are exactly zero. This is a compact smoothstep-based falloff, not Gaussian, HDR, additive lighting or a post-processing bloom. An alpha-zero/disabled lobe must not divide by zero. The existing renderer applies only the real admitted ancestor-clip/target policy, with no extra alpha or sRGB conversion.
