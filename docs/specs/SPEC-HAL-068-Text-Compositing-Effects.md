## **1. Motivation**

Now that text rendering is stable (066) and supports both subpixel and SDF paths (067), Halcyon needs a unified and deterministic **text effects system**.

Requirements:

* Shadow text for UI legibility
* Outlines for high-contrast themes
* Glow for emphasis or accessibility
* GPU-side compositing, not CPU raster hacks
* Effects must be independent of chosen text renderer path
* Effects must not break layout metrics

068 formalizes the compositing model.

### **2.1 Primary**

## **4. Effect Model (CPU Side)**

### **4.1 Data Structure**

Assigned per TextBlock/TextSpan:

```
pub struct TextEffect {
    pub kind: TextEffectKind,
    pub color: Color,
    pub offset_x: f32,
    pub offset_y: f32,
    pub radius: f32,    // glow/blur only
    pub thickness: f32, // outline only
}
```

### **4.2 Effect Kinds**

```
enum TextEffectKind {
    Shadow,      // fixed offset
    Outline,     // SDF analytic expansion
    Glow,        // radial blur
}
```

### **4.3 Multiple Effects**

Each text node stores:

```
pub effects: SmallVec<[TextEffect; 3]>;
```

Order is deterministic:
**Shadow → Outline → Glow → Base Text**

---

## **5. Quad Expansion Rules**

### **5.1 Shadow**

Generate a copy of each base quad:

* Offset by effect.offset_x / offset_y
* Use effect.color
* Same UVs
* Same geometry

### **5.2 Outline (SDF-only)**

Requires MSDF/SDF path.
For native glyphs, fallback to pixel dilation.

Generated by shader using:

```
distance = sample_sdf();
alpha = smoothstep(thickness_low, thickness_high, distance);
```

### **5.3 Glow**

Glow uses:

* Enlarged quad (radius*2 per side)
* Shader-based radial blur of SDF
* Fallback for RGB/subpixel: via precomputed Gaussian kernel

---

## **6. Renderer Integration**

### **6.1 Two Passes Required**

#### **Pass 1 — text_effect_pass**

Renders:

* Shadows
* Outlines
* Glows

alpha-blended **behind** text.

#### **Pass 2 — text_main_pass**

Renders:

* Base text (subpixel, grayscale, SDF)

### **6.2 Pipelines**

Two pipelines:

1. `pipeline_text_effect` (FX)
2. `pipeline_text_main` (base text)

### **6.3 Instance Format**

Extended from SPEC-067:

```
struct TextInstance {
    pos: vec2<f32>,
    uv_min: vec2<f32>,
    uv_max: vec2<f32>,
    color: vec4<f32>,
    render_mode: u32,    // grayscale, subpixel, sdf
    effect_mode: u32,    // none, shadow, outline, glow
    effect_params: vec2, // size/thickness
}
```

## **7. Shader Specification**

### **7.1 Shadow Shader**

```
coverage = sample(atlas, uv)
out = effect_color * coverage
```

### **7.2 Outline Shader (SDF)**

```
d = sample_sdf_atlas()
alpha = smoothstep(width_low, width_high, d)
out = effect_color * alpha
```

### **7.3 Glow Shader (SDF)**

```
d = sample_sdf()
blur = compute_glow(radius, d)
out = effect_color * blur
```

Native glyphs fallback to convolution.

## **8. Text Layout (SPEC-048)**

Unchanged:

* No padding added
* No baseline changes
* Effects render outside logical box

Effect drawing is **pure visual decoration**, not layout.

## **9. Testing Matrix**

### **9.1 Shadow**

* Fractional offsets
* No drift under resizing
* Crisp edges on subpixel text

### **9.2 Outline**

* SDF analytic edge sharpness
* Variable thickness
* Scaling x0.5 → x4

### **9.3 Glow**

* Gaussian stability
* Performance under 1k+ glyphs

### **9.4 Multi-Effect**

* Shadow+Outline
* Shadow+Glow
* Outline+Glow+Shadow

## **11. Implementation Notes**

### **11.1 Performance**

* Shadow cost: +1 quad per glyph
* Outline cost: +1 quad, very cheap
* Glow cost: +1 quad, blur in shader

Expected +40–60% glyph cost for heavy FX text.
