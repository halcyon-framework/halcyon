# SPEC-HAL-400: Host-Native Choice Picker for Touch
Status: Adopted / Active / Binding. Date: 2026-11-21.
Owner decision: JC directly requires standard device-native choice pickers for touch on phones and tablets after physical iPhone acceptance. This overrides only the old Halcyon-popup-only TOUCH presentation restriction in HAL-397 section 3 and HAL-398 section 5. Halcyon remains owner of OptionId, Resolver, focus, capture and commit; HAL-201 original Mouse/Pen/keyboard popup stays intact.
Owners: HAL-002 sovereign InputFusion/EventRouter, HAL-139 host mediation, HAL-199/201 model+resolver, HAL-397 qualified Touch Tap, HAL-398 existing browser window bridge.

## Scope and verification

- Objective: On iPhone, touch an application choice field and use the standard OS-native picker, confirm one OptionId through existing ComboBox Resolver, dismiss with no change; preserve touch pan/kinetic scroll and all current mouse/keyboard routes.
- Standing objective: all Halcyon widgets usable on mobile WebAssembly and native iOS app shell without switching to a separate mobile widget system.
- Delegation and authority: direct new JC UX decision adopted by the delegated technical reviewer; HAL-002/002A, HAL-139, HAL-199/201, HAL-396/397/398/399, PM-014/023/029. Changes in host PRESENTATION only; no altered core selection semantics or locked HAL-131A.
- Source verified: ComboBox::snapshot.items is Vec<(OptionId, String)>; its typed TouchTarget::Control opens the Halcyon popup and TouchTarget::Item invokes existing attempt_commit(CommitSource::Selection). The source adapter must use this actual ordered snapshot and the same explicit Resolver path. Native Webkit HTMLSelectElement.showPicker is unsupported; a real touch-targeted rendered SELECT must receive the actual trusted user gesture, rather than relying on synthetic click/focus/showPicker.
- Scope: existing WidgetTree/ComboBox and browser window transport plus native host choice transport, existing qualification/callback and focused tests. No app-specific HTML widgets, new input engine, global mobile flag or feature gates.
- Verification: real native routed Tap vs Pan and Resolver tests, WASM transport tests and physical iPhone Safari/Brave host picker behavior. Existing desktop Mouse/Pen/keyboard and native shell regressions must remain green. Build/test alone does not prove OS picker appearance.
- Effects: UI-only capability projection; no API, network, stored values, sensitive logs or backend changes.

## Halcyon Pre-Flight
- Governing: HAL-002 sovereign OS transport, HAL-139 native capability, HAL-199/201 Resolver selection, HAL-397/398 Touch/host ingress, this new Binding exception to previous mobile presentation.
- Widget policy: ComboBox still owns control, source projection and current committed state; Resolver alone interprets and authorizes selection. System is solely the choice presentation/input transport.
- Interaction: qualified Touch Tap on select affordance/body, cancel/pan suppress selection; all Mouse/Pen/keyboard behavior unchanged.
- FORBID: direct DOM/OS widget access, OS focus/commit authority, synthetic Mouse events, duplicated gesture engine, background click workaround, stale OptionId, popup click-through and hidden runtime flags.
- Reuse: existing source-qualified touch press, ComboBox OptionSnapshot, current popup revision, original Selection commit transaction, HAL-398 per-window browser bridge. No new standalone app overlay.
- Demo: representative existing ComboBox example with host-device acceptance; Escape remains normal.

## 1. Source and presentation policy
1. A genuine Touch Tap on the enabled noneditable ComboBox body/chevron requests host-native picker presentation of the current ordered options. For a text-enabled ComboBox, Touch Tap on the text region continues HAL-398 editable keyboard behavior; Tap on the distinct selection affordance requests native choices. Disabled/loading/empty controls cannot open.
2. Mouse, trackpad, Pen, physical keyboard, Tab/Shift+Tab, Enter, Escape, hover, captured keyboard navigation, direct popup rows and their original interactions MUST remain the existing Halcyon ComboBox implementation. A hybrid tablet has both modalities simultaneously; no global device/mobile mode, app-specific option or alternate semantics.
3. Only one presentation is active per source/qualified session: a Touch-native picker does NOT also open the Halcyon popup. An admitted Mouse/Pen/keyboard activation still uses the existing Halcyon popup. The choice identity, Resolver outcome and application value are identical for either presentation.
4. OS picker ordering/search/scrolling and row animation are presentation. Browser DOM/OS does not filter, sort, normalize option labels, invent choices or decide application selection. Each current option is projected as exact opaque OptionId with its display label in original order.

## 2. Engine-owned request and result
1. Original HAL-397 Tap qualification checks press ID, pointer source, mount generation, domain, overlay, hit path and current ComboBox option snapshot revision. The engine creates ONE host-choice lease with ordered (OptionId, label), current committed option, and owner identity. No user choice is accepted merely because a host picker opens.
2. The host reports a single explicit user selection of a presented OptionId or Cancel/Dismissal with the original lease and snapshot generation. Engine revalidates actual owner, availability and live projected OptionId, then uses EXACTLY the current ComboBox Resolver-backed Selection path. Resolver rejection is binding; no implicit commit on blur or initial highlight. No event synthesis or double callback from change/blur.
3. Cancellation by overlay takeover, viewport/lifecycle retirement, disable, new options, focus change, a Pan, another picker or invalid host callback retires only that lease, never triggers click-through or changes the previous committed value. Source change cannot silently select an adjacent index or equal label.
4. One host choice surface per relevant window, installed/retired by existing Halcyon host transport lifecycle; no singleton, direct widget DOM calls, extra model or global picker manager. Host-originated callbacks reenter the canonical typed input queue and normal EventRouter, not widget state mutation.

## 3. Real browser and native host activation
1. Mobile WebAssembly uses a REAL touch-hit-testable rendered HTML SELECT with option values mapped to opaque OptionIds and native user-agent picker behavior; it may be optically transparent over the qualified ComboBox selection surface but cannot be display:none or an offscreen proxy, because iOS Safari cannot rely on programmatically calling HTMLSelectElement.showPicker. The trusted touch must actually reach a valid SELECT target for UA opening.
2. The select overlay position follows the Halcyon widget's current mounted and clipped screen rectangle, root viewport, scroll projection, DPR, overlay hierarchy and keyboard occlusion. It has no independent DOM layout authority or page scrolling. Clipped, obscured, retired or disabled geometry cannot intercept events. Synchronize from existing layout snapshot, not unqualified text search or CSS guesses.
3. PointerEvents intercepted by the host SELECT MUST enter the SAME original InputFusion/EventRouter as native canvas input, once, with original source PointerType/PointerId, contact, window, coordinates and ordering. Preserve Mouse/Pen hover, capture, drag, Tab and shortcuts on hybrid tablets. Never synthesize mouse clicks or invent an alternative semantic route. If the host cannot preserve equivalent Mouse/Pen input from a SELECT overlay, do not claim compliant native picker implementation.
4. During touch Down/Move/Up, first run original HAL-397 admission and HAL-396 pan recognition. If movement becomes a Pan, suppress default native select activation and let the existing ScrollArea receive that same contact. Only a successful short Tap may let the host chooser open. The actual browser native select click/activation must occur in trusted user activation, not a timer/Promise/async workaround. Its change result is still routed through the existing explicit Resolver.
5. On non-web native iOS/Android shells, use HAL-139 host capability for a system picker projection (UIKit/Android equivalent), returning the same typed OptionId-or-Cancel to the same Halcyon Resolver. Do not alter the existing native desktop Winit input or install a second widget tree.
6. Platform admission is a factual host capability. If the host has no native picker capability, the original Halcyon popup remains the complete normal selection route; do not create a product setting, feature gate, or misleading half-native HTML list.
7. Never attach a generic DOM shadow interface for arbitrary Halcyon widgets. The SELECT is a narrowly owned OS input transport comparable to the existing HAL-398 text proxy. No custom app-side JavaScript select overlay.

## 4. Acceptance
1. Native qualification tests: Touch Tap body/chevron opens one host choice lease and not Halcyon popup; explicit ID selection goes through exactly one Resolver Selection; Cancel and stale IDs do not change value; Touch Pan starting on selector moves ScrollArea without launching a picker; text-enabled field tap still uses HAL-398 keyboard; native Mouse/Pen/keyboard popup tests unchanged.
2. Browser tests: exact visible option order, mounted instance generation, current selected OptionId, no duplicate change/blur, clip/scroll coordinates, same pointer ingress as canvas and proper touch cancellation. No second source of option search/matching.
3. Physical iPhone Safari and Brave: native OS picker for Country and Business Profile after one Tap; choose and dismiss work; move from control scrolls without picker, keyboard still types in Email, flick remains kinetic. Hybrid tablet physical Mouse/keyboard behavior is unchanged. Native shell picker acceptance separately observed when shell available; no invented device PASS from browser fixture.
4. If a particular WebKit picker cannot open with the admitted trusted gesture, report the observed API/gesture blocker precisely rather than replacing it with a faux native dropdown, unsupported showPicker call or a static disabled control.
